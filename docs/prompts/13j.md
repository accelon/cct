## 1. 鐵律（寫在最前面）

- **13j 不用 page。** `<頁 n>`／`<頁元 n>` 只作閱讀顯示，**不得進 anchor manifest、不得當 xref target**（spec §4.1、§4.4；`cct/AGENTS.md` §4／§6）。
- 引用單位是「書 → 章 → 節 → 項」的 **semantic segment**，不是書頁。詞典會寫「堯典」「周南·關雎」「隱公·經元年」，不會寫「第 1 頁」。
- `13j?page:1` 是歧義的；`yijing?乾` 才是合法地址。
- **不要改經文正文**，不要改 VA，不要為了 xref 重排版面。你只補 `id` 屬性、manifest 與 metadata。
- 本區**不寫 xout**；引用端的事由引用庫工作區負責。

## 3. canonical segment id 規則（回答 handoff §5.5）

1. `id` 用**原文標題**，不用 slug、不用建置序號、不用頁碼。顯示文字保留原樣，`id` 可與顯示文字不同（去空白、去括注）。
2. 標題先做最小清理：去掉所有空白（`由庚  蓼蕭` → `由庚蓼蕭`）；`/`、`?`、`#`、`\` 不得出現在 id（實測現有標題沒有，但要對未來防呆：改用全形或 percent-encode，並在 manifest 記 `label` 原文）。
3. **leaf 標題在該 work 內唯一 → 直接用 bare id**：`乾`、`堯典`、`關雎`、`學而`、`梁惠王上`。
4. **撞名 → 加最少一層祖先**，用 `/` 分隔：`zuozhuan?隱公/經元年`、`邶/柏舟`、`天官冢宰/世婦`。`/` 只是消歧分隔符，不是固定語意層級；不要全部強制 full path。
5. `id` 只需在**所屬 work 內唯一**。跨 work 同名是合法的（`隱公`、`微子`、`緇衣` 等 16 個 bare id 在不同經書重複），因為 work 已消歧；不要為了全域唯一而加書名。
6. 加一層祖先仍撞名 → **視為來源缺陷，回報作者，不要用 `#1`／`#2` 序號掩蓋**（見 §5）。
7. 只有 `<章>` 的 work（周易、儀禮、禮記、論語、孝經、孟子）：`<章>` 本身就是 leaf，直接用章名。爾雅的 `釋詁` 與 `釋詁上`／`釋詁下` 是不同節點，各自給 id。
8. 引用只到 work 層（沒有篇章 hint）：**不要發明一個 work-level anchor**。resolver 會用 `quote_normalized` 比對原文，自然落到某個 segment（spec §7.5）；比對不到就進 `unresolved`。

## 4. `a-b` 的座標空間

- 每個 semantic segment 的 anchor 文字 = **該節點起、到下一個任意語意節點之前的經文**（不含節點標題本身；標題是 `label`，存 manifest）。
- `a-b` 為該段經文的漢字序，0 起右開；標題文字不計入正文，避免座標漂移。
- 一段經文只能屬於一個 anchor；`<頁 n>` 出現在段落中間時**不切斷 anchor**（頁只是顯示分頁）。
- 解析時注意有 1 行是 `<節>凌人</節>𠧤`：節點標籤後還跟著正文，要把殘餘文字算進該 segment，不要整行丟掉。
- 引文若跨越兩個 segment → 引用端須拆成兩筆 link 或降級，不要在這裡把邊界抹掉。
